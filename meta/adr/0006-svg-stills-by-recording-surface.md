# SVG Stills by a recording Surface

A Still renders as SVG through a second backend inside the same `Surface` struct, not through per-Tool emitters. `Surface` holds either a tiny-skia raster or an SVG writer, and every op matches on it, so Tool code is shared by PNG and SVG and never knows which one it draws to. The writer streams elements as ops arrive. Clips become inline `<clipPath>`, and each element drawn inside the `with_clip` closure gets its own clip `<g>`; alpha and multiply are written on each element. All 29 site-SVG Tools record. atlas and kiosk write their hinted glyph outlines as `<path>`, not `<text>`. carve's per-pixel ramps flush as a PNG `<image>`. Nearest buffers (fete, quilt, static) become row-merged `<rect>` grids. Grain and dither are dropped. Ops with no faithful SVG form (blur, plus, Bicubic resampling, radial fade) panic in SVG mode. No site-SVG Tool uses them.

## Considered Options

- **Per-Tool emitters, as the site does for 21 Tools**: richer markup (`<text>`, gradients), but each emitter is a second copy of the Tool's drawing code. Each one can drift from the PNG that the fidelity check proves.
- **`Surface` as a trait, Tools generic over it**: the same effect as the enum, but it means signature churn in 56 files and two compiled copies of every Tool.
- **Always record a display list, replay to raster or SVG**: one code path, but it rewires the proven PNG path and puts every golden at risk for no PNG gain.
- **Real `<text>` for atlas and kiosk**: editable type, but it can't pixel-match hinted outlines, and it needs a font choice (embed ~330 KB per face, or name a stack).
- **carve as a gradient approximation, or unsupported**: the site's approximation fails our own fidelity check. Leaving carve out breaks the 29-Tool parity.

## Consequences

- An SVG is held to the PNG of the same Recipe (max luma ≤ 1, clipped ≤ 8/13). It is not checked against the site's SVG.
- The writer's output rules are fixed by measured resvg drift: `<path>` not `<circle>`, per-element opacity, `stroke-miterlimit="10"`. A path or stroke that misses the frame writes nothing, and a polyline stroke drops each run of segments past the frame but keeps one segment beyond each in-frame one, so its in-frame joins are unchanged. Path points are relative deltas that svgtypes sums in `f64` back to the target, at the fewest digits that land on it; a segment is absolute when that is shorter. A fill inside the frame only needs to land on its 1/256 px edge, since tiny-skia truncates points to that grid. A fill the frame clips must land on its exact `f32`, because the clipper cuts curves before snapping. So must a stroke, since the stroker offsets in float: a stroke snapped to the edge drifted 28 luma, and one within 1e-4 px drifted 14. A transformed path writes its `matrix` and lands on exact `f32` too, because tiny-skia maps the path before snapping; an identity transform writes the plain path. A stroke names one CSS class per distinct paint in a `<style>` at the document head and rides in the open smooth ink group. Runs of one ink and edge mode share a `<g fill>`, with `shape-rendering="crispEdges"` for rects. A partial-pixel rect overrides that `fill` when its shifted ink differs, and writes `fill-opacity` at 4 digits, since resvg rounds opacity to a u8. A faded element writes the ink that resvg premultiplies by that u8 to tiny-skia's f32 product. A faded stroke under 1 px is a hairline, so it also picks the opacity whose u8 tiny-skia scales by the width to the raster's alpha. A multiplied stroke writes one blend group per subpath, because tiny-skia blends each hairline segment on its own. A ramp writes a `userSpaceOnUse` `<linearGradient>` with `f32` points and stops, which resvg turns back into the same tiny-skia shader. A clip writes each clipped element in its own `<g clip-path>`, because tiny-skia masks each draw and a shared group would mask the composite once. That group takes a no-op `feOffset` filter whose region is the frame, so resvg's layer, and the rect it clips the clip path to, is the frame as in tiny-skia. A `<clipPath>` closes the open ink group, so it never inherits `crispEdges`. A nested clip names its outer clip on its `<clipPath>`, which resvg intersects as tiny-skia does masks. Under a clip, a stroke of 1 px or less writes each subpath in its own clip group, because tiny-skia masks each hairline segment on its own and crossings on the clip edge drift by up to 18 luma otherwise. A Nearest buffer writes one crisp `<rect>` per run of same-ink cells along a row, with cell edges from the raster's sampler. Pixel writes collect until the next element, then flush as one PNG `<image>` cropped to their bounds; the root declares `xmlns:xlink` only then.
- carve's SVG is partly raster. The docs say so.
- A new op added to `Surface` needs an SVG arm, or it panics in SVG mode.
- Adding a per-Tool emitter later is a new decision, not a hook that already exists.
